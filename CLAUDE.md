# CLAUDE.md

AI meeting assistant for the Inter IIT Tech Meet 15.0 Bootcamp (Phase 2, ML PS). It takes an English meeting recording and produces a transcript plus a structured meeting record.

## Pipeline

One workflow. The stages run in this order and no other:

| # | Stage | Input | Output |
|---|-------|-------|--------|
| 0 | Audio validation | uploaded file | validated audio path, or an error |
| 1 | Speech-to-text (faster-whisper) | audio | **raw transcript** with segment timestamps |
| 2 | LLM #1: refinement | raw transcript | **refined transcript** with domain terms corrected |
| 3 | LLM #2: documentation | refined transcript | summary, minutes, key decisions, action items |

- Stage 3 is a separate stage with its own prompt. Where possible it uses a different model from stage 2.
- A stage runs only if the stage before it succeeded. If a stage fails, the pipeline stops there.

## Stack

- Python 3.10+, faster-whisper, Streamlit, python-dotenv.
- Secrets (API keys, model names, endpoints) go only in `.env`, loaded with python-dotenv. Never hardcode them, never commit `.env`. Keep `.env.example` up to date with every variable name and no values.

## Layout

Each stage is its own module, and each LLM stage has its own prompt file in `prompts/`. The planned layout (update this section when the real layout differs):

```
app.py                  # Streamlit UI, calls the pipeline only
pipeline/
  validation.py         # stage 0
  transcription.py      # stage 1
  refinement.py         # stage 2
  documentation.py      # stage 3
  errors.py             # one exception class per stage
  runner.py             # runs stages in order, stops on first failure
prompts/
  refinement.md
  documentation.md
```

- Load prompts from `prompts/` at runtime. Do not write prompt text inline in Python.
- Keep UI code out of the pipeline modules, so the pipeline can run without Streamlit.

## Hard rules

These are requirements of the problem statement. Do not relax them, even temporarily.

### Validation and errors
- If audio is empty, silent, unreadable or in an unsupported format, stage 0 raises a clear error **before any later stage runs**. Nothing downstream may execute: no transcription and no LLM calls.
- Catch errors per stage. Every error message names the stage that failed (e.g. `Stage 1 (transcription) failed: ...`), and the UI shows it.
- Never swallow an error and carry on with partial or empty data.

### Transcripts
- The raw transcript is never modified after stage 1. Treat it as immutable; refinement produces a new object.
- Raw and refined transcripts are always stored and shown separately, never merged or overwritten.
- Refinement only corrects domain-specific terms. It must keep **names, numbers, negation and commitments** exactly as spoken. "We will not ship Friday" must never become "We will ship Friday."

### No speakers
- There is no speaker detection or diarization, and there are no speaker labels (`Speaker 1`, `SPEAKER_00`, guessed names before lines, etc.) anywhere: transcripts, prompts, outputs or UI. Do not add them.

### Documentation output
- Never invent task owners or deadlines. Use the literal string `"unspecified"` when the recording does not state them.
- An owner must be a name that actually appears in the transcript. Check this in code after the LLM call, not only in the prompt.
- Never present a proposal or suggestion as an agreed decision. Never present an unstated or tentative assignment as a confirmed task.
- The Markdown record (for people) and the JSON record (for machines) must contain **identical** decisions and tasks. Generate both from one structured object (JSON first, then render Markdown from it) so they cannot drift.

### No canned output
- No prewritten, hardcoded, cached or sample outputs used as results. Every transcript and record is generated by the pipeline for each new recording. Test fixtures belong in tests only, never in the app's code path.

## Working on this repo

- Run the app: `streamlit run app.py`
- The local `.venv` was created with Python 3.14. faster-whisper depends on ctranslate2, which may not ship wheels for very new Python versions. If installation fails, recreate the venv with Python 3.10–3.12.
- When changing a prompt, re-check it against the hard rules above, especially the rules on owners, deadlines, proposals vs. decisions, and preserving negation.
